RFC: Short descriptive title
============================

:Status: Draft
:Authors: GitHub handles or names
:Created: YYYY-MM-DD
:Updated: YYYY-MM-DD
:Discussion: Link to the issue or discussion, or ``None``
:Implementation: Links to implementation pull requests, or ``Not started``

Summary
-------

Describe the decision and its user-visible result in a short paragraph.

Motivation
----------

Describe the problem, who experiences it, supporting information, and why
the current behavior or architecture is insufficient.

Goals and non-goals
-------------------

Goals
~~~~~

- List the outcomes this RFC must achieve.

Non-goals
~~~~~~~~~

- List adjacent problems this RFC intentionally does not solve.

Proposal
--------

Describe the design precisely enough that an implementation can be reviewed
against it. Include ownership boundaries, data flow, failure behavior, and the
smallest useful version of the change.

Public interfaces and configuration
-----------------------------------

List additions or changes to APIs, wire contracts, configuration, command-line
interfaces, persisted formats, artifacts, and observable behavior. State
``Not applicable`` if none change.

Compatibility and migration
---------------------------

Explain compatibility with existing clients, deployments, data, artifacts,
and configuration. Include rollout, rollback, migration, and deprecation plans.

Security, privacy, and trust boundaries
---------------------------------------

Identify new inputs, privileges, credentials, network surfaces, data retention,
or changes in which component is trusted to make a decision. State how misuse
and partial failure are contained.

Operations and observability
----------------------------

Describe resource costs, scaling limits, metrics, logs, alerts, debugging, and
operator-visible failure modes.

Testing and documentation
-------------------------

Describe the contract, unit, integration, acceptance, migration, and failure
tests required. List the user and developer documentation that must change.

Alternatives considered
-----------------------

Describe credible alternatives, including keeping the current behavior, and
why this proposal is preferred.

Risks and unresolved questions
------------------------------

List known risks, assumptions, open decisions, and verification still needed.

Implementation plan
-------------------

Break the work into independently reviewable stages. Identify which stage
creates a compatibility commitment and how incomplete rollout remains safe.

Decision record
---------------

Maintainers complete this section when the RFC is accepted, rejected,
withdrawn, implemented, or superseded. Record the date, decision, rationale,
conditions, and links to any replacing or implementing work.
